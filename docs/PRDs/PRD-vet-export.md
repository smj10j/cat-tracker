# PRD: Vet Visit Export

**Status:** Implemented
**Scope:** New /cats/:id/export page + export buttons on profile and health guidance pages

---

## Problem

Users tracking a cat with health concerns have no way to share that data with their vet. The information exists in the app but can't easily leave it. A vet visit is most useful when the owner arrives with a concrete record: weight trend, behavioral changes over time, and any detected patterns.

---

## Solution

A print-optimized export page at `/cats/:id/export` that consolidates everything a vet needs into a single readable document. The user prints it (or saves as PDF via browser) and brings it to the appointment.

### Entry points

- **Cat profile page** — small "Export" button in the top-right header area next to "Edit"
- **Health guidance page** — button in the action area, surfaced when a cat's status is watch/concerning/urgent (where a vet visit is most likely)

### Export page content

Structured as a document with clearly labeled sections:

1. **Header** — cat name, "Vet Visit Summary", generated date
2. **Cat info** — name, breed, age, coloring, notes
3. **Weight summary** — current weight, peak weight, % change from peak, health status label, rate of change, brief clinical context
4. **Recent weight log** — table: date | weight | change (last 10–15 entries)
5. **Behavioral measurements** (for each type that has data) — type label, most recent value, last 4 weeks of entries
6. **Detected patterns** — the correlation findings in plain language (same as InsightsPanel)
7. **Footer** — "Generated by Cat Tracker" + date

### Format

- Rendered as a light-background web page — printable directly from the browser ("Print" → "Save as PDF")
- Print CSS hides the bottom nav and print button
- No external PDF library needed — browser handles layout and page breaks
- Monospace data tables for weight log; readable prose for patterns

### Accessibility for vets

The export is written so a vet can scan it without knowing the app:
- No internal jargon (no "scale unit", no "ok/watch/concerning" without explanation)
- Behavioral values shown as human-readable labels (e.g., "Most", "None", "Normal") not raw numbers
- Status explained: "Concerning — lost 7% from peak weight" not just "concerning"

---

## Non-goals

- Email/share directly from the app (clipboard copy of URL is sufficient for now)
- PDF generation via server (browser print is sufficient)
- Charts in the export (static chart images would require canvas capture; adds complexity without proportional value)
